# 论坛实现与演示

沿用 HTML/CSS/JavaScript、Express 和 MongoDB，不新增依赖。

## 存储

MongoDB `posts` 集合保存帖子：标题、正文、分类、作者 ID、作者昵称、创建时间。评论保存在该帖的 `comments` 数组中，每条包含自己的 ID、作者、正文、时间。评论通过 MongoDB `$push` 原子追加，避免同时评论时互相覆盖。列表按发布时间倒序，每页 20 条。启动时从 `data/forum-seed.json` 补入四个分类各一篇示例帖，每篇带一条示例回复，标题和作者明确标注“示例”。固定 ID 配合 `$setOnInsert` 防止重启重复插入或覆盖已有内容、真实回复；示例作者不创建登录账号。

## 权限与安全

复用 HttpOnly Cookie 和 MongoDB sessions 会话。写入接口每次根据服务端 session.userId 查询用户，不接受浏览器传入的作者身份。游客读取接口开放，写入返回 401。复用同源校验和 JSON 限制；标题 1–100 字，正文 1–2000 字，评论 1–1000 字，分类只接受四个固定值。前端把帖子、评论和昵称转义成纯文本显示，不执行用户 HTML。发布按钮防重复提交，服务端写入限流。

## 接口

- `GET /api/forum/posts?category=all&page=1`：帖子列表、评论数量与分页。
- `POST /api/forum/posts`：登录后发帖，JSON 字段 title、content、category。
- `GET /api/forum/posts/:id`：公开读取帖子及评论，返回当前登录用户是否为作者（isOwner）。
- `DELETE /api/forum/posts/:id`：仅作者可删除讨论及其评论。确认后发送请求，MongoDB 同时匹配帖子 ID 和会话用户 ID。
- `POST /api/forum/posts/:id/comments`：登录后评论，JSON 字段 content。
- 保留原有 `GET /api/forum/access` 权限接口。

## 本地发帖草稿

发帖表单按账号 ID 在当前浏览器自动保存标题、正文、分类和更新时间。再次打开发帖页时，可恢复草稿或确认放弃。草稿保存在该网站地址对应的浏览器存储中。换浏览器、设备或清除网站数据后，原草稿无法恢复。

服务端确认发布后清理对应草稿。网络断开、超时或响应异常时保留草稿。如果界面提示发布结果未确认，先到讨论列表核对再决定是否重试。同一账号的草稿供一个编辑页使用。另一个标签页更新草稿后，旧编辑页会提示保存失败，避免覆盖新版本。

## 1–2 分钟演示

1. `npm start` 后进入论坛，游客查看列表和已有帖子；点击“发布讨论”进入登录页并看到登录提示。
2. 使用已有账号登录（或注册一个自己的演示账号），点击“发布讨论”。
3. 填写标题、正文和分类，发布后自动打开详情。
4. 填写评论，提交后评论区和数量立即更新。
5. 刷新，帖子和评论依然存在；退出登录后仍可阅读，但提交必须先登录。

首次启动即可浏览示例帖子和回复，也可以登录后继续参与讨论。测试使用随机命名的独立测试数据库，结束后清理，不影响正式账号与帖子。

帖子详情的「···」菜单向作者提供删除操作，示例帖子保留用于演示。
